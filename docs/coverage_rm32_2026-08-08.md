# rm32/ consolidated coverage report — 2026-08-08

Scope: the portable core crate (`rm32/src`) only, at merge commit
3c12d5a (post second origin/main merge).

Method: `cargo llvm-cov` instrumentation over BOTH test layers,
profiles merged into one report:
1. Host unit tests: `cargo test -p rm32` — 295 tests.
2. Blackbox vectors: all 80 vectors in `tests/blackbox/vectors/`
   driven by pytest through the instrumented `rm32_harness` binary
   (debug build; release-built harness profiles are ignored by the
   report's object discovery — build debug for coverage runs).

## Notable results

- The vector layer is load-bearing: unit tests alone gave 70.2%
  regions; merging the 80 vectors lifted main_state 71->94%,
  isr_logic 77->94%, control/input 74->100%, harness itself 0->94%.
- **sounds.rs: 0.00%** — NOT dead code: it is the boot startup tune
  (`Sounds::play_startup`, called once from firmware main, blocking
  AM32-port style). It never runs under harness/unit tests. It also
  OVERLAPS the newer non-blocking `tone.rs` scheduler (91.95%) that
  drives beacons/arming tunes — consolidation candidate: port the
  startup tune onto ToneScheduler and delete sounds.rs, or add a
  host test with mock HAL.
- **shared_comm.rs 24.6% / hal.rs 25%** — mostly unexercised default
  trait method bodies (TestShared/mocks override them). Low value to
  chase; some defaults may be genuinely dead.
- **shared_state.rs 66.6%** — the real SharedState is exercised by
  the harness, but the bench debug accessors (dbg_* counters, ring
  diagnostics) have no host consumers. Expected; bench-only surface.
- **input_mapping.rs 77.3% lines** — the rc-car and servo-bidir
  mapping variants are only partially vectored (matches the honest-
  gaps list: RC-car reverse untested).
- **config.rs 81.6% / reset_cause.rs 73.3%** — version-migration
  arms and rarely-hit reset flags lack cases.
- Fully covered: bemf, current, filter, motor_mode, ntc, pid,
  telemetry, units, control/input.
